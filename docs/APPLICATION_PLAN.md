# Personalized application timetable

Open **My application plan** from the dashboard, My list or deadline tracker. A plan is generated on arrival from the signed-in student's chosen schools, intended programmes, current imported supplements, entered deadlines, linked essays and checklist progress. It needs no AI key or AI consent. No student work is sent to a provider for scheduling.

1. Add schools and the actual intended programme/application platform to My list. Enter each relevant deadline, time, time zone and source. Dates in the plan are **entered records**, not independently verified official deadlines. Historical CDS month/day fields are not converted into invented current-cycle dates.
2. Set available days, weekly hours, start time, time zone, planning horizon and desired submission buffer. Initial defaults are explicitly shown: six hours/week, selected weekdays, UTC and an eight-week horizon. **Use computer time zone** fills the zone; save to apply changes. Availability is saved privately across restarts.
3. Review optional, choice and conditional prompts. Only entries labeled exactly Required are auto-included; the student selects other applicable responses and verifies any “choose X” rule. The system does not claim to infer programme eligibility from a major name.
4. Read the timetable. It includes source/route verification, school-and-major research, prompt-specific brainstorming, drafting, revision, final read, document preparation, separately entered deadlines and submission checks. Clear upload/submission tasks such as graded-paper, portfolio or video submissions are planned as material preparation rather than new essay drafts. Links open the exact school research page, supplement setup or linked essay. Existing unlinked shared statements are reused once per explicitly selected Common App/UCAS platform; otherwise a shared statement is planned once with instructions to confirm that it is required. Multiple candidate shared drafts produce a selection warning. Existing school essays must be linked to their list entry to reliably avoid duplicate estimates.
5. Mark a task complete after completing the whole task, including all its sessions. Linked essay statuses can automatically complete earlier writing stages; nonempty text alone does not finish a draft. Submitted applications stop generating initial application tasks; outstanding separately entered aid/interview/other non-application deadlines remain planned. Denied or withdrawn applications are excluded. A completed essay checklist also completes imported prompt-writing stages. Changes recalculate remaining sessions on page load, refresh, preference save or completion update. Marking a planning task complete never submits an application or edits essay status.
6. Download `.ics` to add work sessions to a calendar. It is a private snapshot, not a subscribed calendar or notification service. Replace the prior import after changes to avoid duplicates. No email reminders or background messages are sent by this feature; GitHub issue #9 remains separate.

## Planning rules and limits

- Suggested milestones work backward from each entered deadline and submission buffer: verify 28 days ahead, research 24, brainstorm 18, draft 12, revise 7, final read 2, submission 0 (each in addition to the buffer). Future deadlines with a lead date already past compress that milestone to today. A missing application deadline uses the chosen planning horizon and remains explicitly flagged. A selected round never borrows a different round's early deadline; a generic application deadline may be used when available.
- Tasks are scheduled into the student's selected days, prioritizing suggested targets and writing-stage order. Work blocks are at most 45 minutes with 10-minute gaps. The weekly availability budget includes breaks and is distributed conservatively across selected days into a window beginning at the chosen start time. Sessions never extend past that window or midnight, and do not use time already passed today. Availability applies to application work only; exams, holidays and school commitments need to be reflected by the student's settings. There is no external calendar free/busy integration.
- Estimated writing time varies with published word limits and essay stage. Character limits are not converted into word limits. Estimates are planning aids, not promises; external recommendation/transcript/test-processing times are excluded. Shared UCAS setup avoids a 650-word default, but the generic editor is not the official three-box character validator.
- Work after a suggested target is flagged. Work outside available capacity remains explicitly unscheduled with its remaining minutes; it is never silently dropped or represented as finished. Incomplete deadline time/source/local-zone records also require confirmation; missing times use the existing end-of-day fallback for planning, not a verified closing time. Past deadlines, missing prompts and unresolved selections are visible warnings. Local daylight-saving clock-change days are skipped to avoid ambiguous/nonexistent wall-clock sessions; urgent work on those days needs manual arrangement.
- Work dates and deadlines carry their respective time zones. Calendar events are exported in UTC with exact-minute start/end times. The original entered deadline, time-zone and source note remain visible.
- Completed task IDs are stable; changed prompt wording creates new IDs rather than reusing old completion. Completion state and availability are encrypted with a separate application-schedule purpose and stored per account. They are included in data export and removed by account-deletion cascade. API mutations only accept tasks in the signed-in owner's current plan.

This update generates the plan automatically when viewed; it does not independently crawl and certify school deadlines, enforce programme eligibility, submit forms, schedule recurring app automations or send notifications.

Desktop builds exclude prior bundles, research caches, development mail, local profiles and environment files; a second packaging filter and payload check reject accidental local data. The package includes only the generated starter reference database.
